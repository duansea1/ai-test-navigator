# 测试设计 Skill

目标：每条需求产出可执行、可验收的测试用例，五类覆盖不缺角。

规则：
1. **functional（功能正向）**：按验收标准逐条正向验证，一条验收标准至少一条用例。
2. **negative（异常反向）**：非法输入、错误凭证、越权访问、空值/超长值——验证系统拒绝且报错可理解。
3. **boundary（边界）**：数量上限、超时阈值、分页边界、字符长度边界（0/1/上限/上限+1）。
4. **idempotency(幂等)**：重复提交、重试、并发相同请求——验证不产生重复数据或副作用。
5. **security（权限）**：未登录、跨角色越权、水平越权（A 的凭证访问 B 的资源）。
6. P0 需求五类都要有；P2/P3 至少 functional + negative。
7. steps 是可执行步骤（谁、做什么、看什么），expected 是可判定的预期结果（不是「正常」两个字）。
8. 需求未说明的行为（未定义的错误提示文案等）不臆测，expected 写「按需求定义」并标待确认。
