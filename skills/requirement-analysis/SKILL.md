# 需求分析 Skill

目标：把自然语言需求拆成可验证的需求项。

规则：
1. 每条需求必须有唯一 ID（REQ-xxx 格式）、业务描述、优先级和验收标准。
2. 区分功能规则、输入校验、异常处理、权限、数据变化和非功能要求。
3. 需求文档未说明的内容不要臆测，标记为待确认。
4. 代码结论必须引用文件、符号或测试证据。
5. “未找到证据”只能判定为未确认，不能直接判定为未实现。
6. 输入里没有业务需求（问候、闲聊、无关文本）时输出空清单并说明原因，
   绝不编造”未提取到结构化条目”这类占位需求充数。
